# Implementation Plan: Forward-Only SOP Workflow

**Branch**: `018-remove-multi-answer-volunteer` | **Date**: 2026-06-20 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/018-remove-multi-answer-volunteer/spec.md`

## Summary

Remove the User Story 2 "multi-answer skip detection" behavior from the SOP Workflow (`010-sop-workflow`). Replace with a strictly forward-moving state machine that processes only the current pending step on each turn, plus a per-step re-ask counter (default limit: 3) that skips a step after the visitor fails to answer it the configured number of times.

The core change is confined to `advancer.ts` (filter skip-detector output to the pending step only; add re-ask counter logic) and `state-machine.ts` (remove `reset_step` action). Supporting changes: add `reask_count` to the `SOPStateStep` schema, add a `SOP_REASK_LIMIT` constant, delete the US2 E2E walk spec, and remove the dead correction-signal block from `advancer.ts`.

**Goal**: Make the new tests pass. Remove multi-step and correction-signal code.

**Tasks**:

6. **Edit `packages/api/src/lib/sop/advancer.ts`**

   a. **Remove correction-signal block** (lines ~117–164): remove the `caseTypeCorrection` / `subTypeAlsoCorrected` detection and the `reset_step` dispatch.

   b. **Filter skip-detector output to pending step only**: after the `detectSkippedSteps` call, find the single match whose `step_id === pendingStepBefore?.id`. Discard all other matches.

   c. **Add `incrementReaskCount` helper** (private to this file):
   ```typescript
   function incrementReaskCount(
     state: SOPState,
     stepId: string,
     limit: number,
   ): SOPState {
     const idx = state.steps.findIndex((s) => s.step_id === stepId);
     if (idx === -1) return state;
     const currentCount = state.steps[idx]!.reask_count ?? 0;
     const newCount = currentCount + 1;
     const updatedSteps = state.steps.map((s, i) =>
       i === idx ? { ...s, reask_count: newCount } : s,
     );
     if (newCount >= limit) {
       // Apply skip_step action, then write the reask_count onto the result
       const skipped = advanceSOP(
         { ...state, steps: updatedSteps },
         { type: 'skip_step', step_id: stepId },
         /* sopConfig passed from outer scope */
       );
       return skipped;
     }
     return { ...state, steps: updatedSteps };
   }
   ```
   Note: The helper needs `sopConfig` passed from the outer `advanceForVisitorMessage` scope. Implement as a nested call or pass `sopConfig` as a parameter.

   d. **Update the no-match branch**: when `currentMatch` is null (no capture for pending step), call `incrementReaskCount(state, pendingStepBefore.id, SOP_REASK_LIMIT)` and return the result.

   e. **Remove import of `reset_step`-related symbols** (if any explicit import of the removed action type existed).

   f. **Import `SOP_REASK_LIMIT` from `@legal-chatbot/shared/constants/sop`**.

## Notes

- `skip-detector.ts` is NOT deleted. It remains the chip/date matching engine for the single current pending step. Only its call site in `advancer.ts` changes.
- `inferred` field on `SOPStateStep` is retained for historical sessions and for chip-tap captures. Under the new model all new captures will have `inferred: false` (direct answer to the pending step) or `inferred: false` from a chip tap. A future cleanup can remove `inferred` if desired.
