# Contract: Log Event

**Owner**: Foundation feature (`001-foundation`)
**Source of Truth**: §11.7 (Observability), Constitution Principles V & VI.

This contract defines the unit emitted by the structured-JSON logger
that every package will use. Downstream consumers (Netlify log stream,
future log-aggregation tooling) will rely on the shape being stable.

## Output Shape

One JSON object per line, written to:

- `stdout` for `level` ∈ {`info`, `debug`}
- `stderr` for `level` ∈ {`warn`, `error`}

```jsonc
{
  "ts": "2026-05-23T12:34:56.789Z",
  "level": "info",
  "event": "message_received",
  "session_id": "sess_abc123",
  "account_id": "acct_xyz",
  "payload": {
    "message_length": 42,
    "is_first_turn": false
  }
}
```

## Field Definitions

| Field | Type | Required | Notes |
|---|---|---|---|
| `ts` | string (ISO 8601 UTC) | yes | Generated by the logger; never user-supplied |
| `level` | enum `info`/`warn`/`error`/`debug` | yes | |
| `event` | string | yes | Stable event name; see "Standard Events" below |
| `session_id` | string | optional | Present whenever a session is in scope |
| `account_id` | string | optional | Present whenever an account is in scope |
| `payload` | object | optional | Event-specific; passes through redaction |

Top-level fields beyond these MUST NOT be added by callers; arbitrary
data goes inside `payload`.

## Redaction

Before serialization, the logger walks `payload` recursively and
replaces values whose **key name** matches any of the following
case-insensitive substrings with the string `"<redacted>"`:

- `apikey`
- `api_key`
- `key_hash`
- `password`
- `password_hash`
- `session_secret`
- `authorization`
- `cookie`
- `set-cookie`

Redaction is applied to the entire `payload` tree, including arrays
and nested objects. Top-level fields (`session_id`, `account_id`)
are NEVER redacted because they are required for correlation.

## Standard Events (per §11.7)

The following event names are reserved for the agent runtime
(consumed in `004-chat-api-agent`); the Foundation pre-allocates
them so logs are queryable consistently.

| `event` | Where emitted | Standard payload keys |
|---|---|---|
| `message_received` | When a chat turn begins | `message_length`, `is_first_turn` |
| `tool_called` | When the agent invokes a tool | `tool`, `params_summary` |
| `context_retrieved` | When `searchContext` returns | `files`, `scores`, `tokens_assembled` |
| `response_sent` | When streaming completes | `tokens_in`, `tokens_out`, `finish_reason` |
| `error` | On any caught error | `error_type`, `error_message`, plus call-site context |
| `injection_attempt` | Per §11.2 — Phase 3 | `pattern_matched` |
| `lead_captured` | Per §7.4 — Phase 5 | `classification`, `lead_id` |

Foundation provides the logger module; it does NOT itself emit any
of these events at runtime. Phase 3+ features call `logger.event(…)`.

## Module API

```ts
// packages/shared/src/logger/logger.ts
export interface LogContext {
  session_id?: string;
  account_id?: string;
}

export interface Logger {
  event(name: string, payload?: Record<string, unknown>, ctx?: LogContext): void;
  warn(message: string, payload?: Record<string, unknown>, ctx?: LogContext): void;
  error(err: Error, payload?: Record<string, unknown>, ctx?: LogContext): void;
  debug(name: string, payload?: Record<string, unknown>, ctx?: LogContext): void;

  enableSessionDebug(sessionId: string): void;
  disableSessionDebug(sessionId: string): void;
}

export const logger: Logger;
```

The default export is a process-wide singleton; tests may construct
isolated instances via a factory if needed.

## Per-Session Debug Mode

When `logger.enableSessionDebug(sid)` is called, subsequent log
emissions whose `session_id === sid` include richer detail (full
system prompt, full tool-call payloads). The flag is in-memory and
reset on process restart. No HTTP toggle is exposed by Foundation.

## Tests

Tests in `packages/shared/src/logger/logger.test.ts` MUST verify:

- A normal `event()` call produces a line of valid JSON with all
  required fields.
- `error()` captures `err.name`, `err.message`, `err.stack`.
- Redaction replaces values for every redacted key name (top-level
  and nested).
- Redaction does not strip non-secret fields with similar names.
- Per-session debug flag adds debug fields only for the marked
  session.
- `level: error` writes to `stderr`, others to `stdout`.

## Constitution Compliance

This contract enforces Constitution Principle V: "Logging MUST NOT
record API keys, password hashes, session secrets, or full PII in
plaintext." The redaction step is the binding mechanism.
