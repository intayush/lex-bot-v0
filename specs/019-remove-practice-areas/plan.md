# Implementation Plan: Remove Practice Areas — Consolidate on Case Types

**Branch**: `019-remove-practice-areas` | **Date**: 2026-06-20 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/019-remove-practice-areas/spec.md`

## Summary

Remove the "Practice Areas" section from the Configuration page and make SOP Case Types the single source of truth for in-scope legal areas. Key changes: (1) promote `out_of_scope_response` to a top-level config field with a read-time migration for old accounts, (2) rename `/api/config`'s `practice_areas` field to `in_scope_case_types` derived from case types, (3) remove the legacy fallback in the system prompt composer, and (4) update all widget consumers and test fixtures. No database migration script is required.

## Technical Context

**Language/Version**: TypeScript (strict), Node.js 20+

**Primary Dependencies**: Zod (schema), Next.js (dashboard + API routes), React (dashboard form), pnpm workspaces + Turborepo

**Storage**: `configurations.config_json` plain text column — no new DB columns, no migration script. Read-time migration in code handles old rows.

**Testing**: Vitest (unit + integration), widget component tests

**Target Platform**: Netlify Functions (API), CDN/NPM widget bundle, Next.js dashboard

**Project Type**: Monorepo — `packages/shared`, `packages/api`, `packages/widget`

**Performance Goals**: No new queries; `/api/config` already fetches `case_types`.

**Constraints**: Widget API rename is a breaking change for old pinned bundles. `QuickReplies` must guard against `undefined` input with `?? []`.

**Scale/Scope**: 3 packages, ~10 files changed. No DB migration. No new API endpoints.

## Implementation Phases

### Phase 0 — Shared Schema: Foundation

**Goal**: Update the shared schema so all packages can compile against the new types.

1. In `packages/shared/src/schemas/configuration.ts`:
   - Add `out_of_scope_response: z.string().default('')` to `configurationSchema` (top level, after `persona`).
   - Change `practice_areas: practiceAreasSchema` → `practice_areas: practiceAreasSchema.optional()`.
   - Keep `practiceAreasSchema` as a deprecated export for the migration shim.
2. Verify: `pnpm --filter @legal-chatbot/shared exec tsc --noEmit`.

**Checkpoint**: `Configuration` type has `out_of_scope_response: string` at top level; `practice_areas` is `PracticeAreas | undefined`.

---

### Phase 1 — API: Read-time Migration + System Prompt + /api/config

3. In `packages/api/src/lib/config.ts` — wherever `config_json` is parsed — add migration shim:
   ```
   if (!config.out_of_scope_response && config.practice_areas?.out_of_scope_response) {
     config.out_of_scope_response = config.practice_areas.out_of_scope_response;
   }
   ```

4. In `packages/api/src/lib/system-prompt.ts`:
   - Remove `computeInScopeAreas` function.
   - Inline: `const inScopeAreas = (caseTypes ?? []).filter(ct => ct.is_in_scope).sort((a,b) => a.position - b.position).map(ct => ct.label);`
   - Change `config.practice_areas.out_of_scope_response` → `config.out_of_scope_response` (line 63).
   - Remove `sopActive` variable (no longer needed).

5. In `packages/api/src/app/api/config/route.ts`:
   - Replace `practice_areas: [...config.practice_areas.active, ...config.practice_areas.custom.filter(Boolean)]`
   - With `in_scope_case_types: caseTypes.filter(ct => ct.is_in_scope).sort((a,b) => a.position - b.position).map(ct => ct.label)`

6. In `packages/api/src/lib/system-prompt.test.ts`:
   - Add `out_of_scope_response: 'Test deflection'` to `testConfig` at top level.
   - Remove test: `'SOP path with empty case_types falls back to legacy practice_areas'`.
   - Update `'out-of-scope deflection text...'` test to assert `config.out_of_scope_response`.
   - Update `'legacy path (no SOP)...'` test to expect empty in-scope list (not practice_areas fallback).

7. In `packages/api/src/db/seed.ts`:
   - Remove `practice_areas` object from seeded config.
   - Add `out_of_scope_response: "I'm not able to help with that area..."` at top level.

**Checkpoint**: `pnpm --filter @legal-chatbot/api exec tsc --noEmit` passes. API system-prompt tests pass.
