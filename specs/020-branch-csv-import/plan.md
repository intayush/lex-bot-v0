# Implementation Plan: Branch Configuration CSV Import

**Branch**: `020-branch-csv-import` | **Date**: 2026-06-20 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/020-branch-csv-import/spec.md`

## Summary

Add CSV import and template download to the branch editor. A new pure utility module (`branch-csv.ts`) handles all parsing, validation, and template generation. Two new API routes expose the functionality. The existing `BranchEditor` dashboard component gains two buttons and an inline import state machine that leads the lawyer through: pick file → upload/validate → preview questions → save as draft.

No new database tables or columns. The import reuses `handleSaveBranch` to create a new `BranchVersion` draft.

## Technical Context

**Language/Version**: TypeScript (strict), Node.js 20+

**Primary Dependencies**: Zod (validation), Next.js route handlers, React state (dashboard)

**Storage**: No new DB columns. Import creates `BranchVersion` rows via the existing `handleSaveBranch` path.

**Testing**: Vitest (unit tests for `branch-csv.ts`; integration tests for the two new route handlers)

**Target Platform**: Netlify Functions (API), Next.js dashboard

**Project Type**: Monorepo — `packages/api` only (no widget or shared changes)

**Performance Goals**: Parse + validate a 200-row CSV and return preview within 5 seconds

**Constraints**: 500 KB file size limit. Server-side parsing only — no client CSV library. Constitution IV: stateless serverless function, no filesystem writes.

**Scale/Scope**: 3 new files, 2 new route files, 1 existing component updated. No DB migration.

## Implementation Phases

### Phase 0 — Pure Utility: `branch-csv.ts`

**Goal**: The parser, validator, and template generator — pure functions, no I/O.

1. Create `packages/api/src/lib/branch-csv.ts` with:
   - `parseAndValidateCsv(csvString: string): { ok: true; questions: BranchQuestion[] } | { ok: false; errors: CsvError[] }` — parse rows, group by `question_position`, run all FR-011 validations, return structured result.
   - `generateTemplateCsv(caseTypeSlug: string, subTypeSlug: string): string` — returns the static template CSV string with 3 example Car Accident questions.
   - `CsvError` type: `{ row: number; column: string; message: string }`.
   - Internal helper: `stripBom(s: string): string` — removes UTF-8 BOM.

2. Create `packages/api/src/lib/branch-csv.test.ts` with full coverage:
   - Happy path: 2 questions × 3 chips → correct `BranchQuestion[]`
   - Slug format error → correct row/column in error
   - Score weight out of range → correct error
   - Missing required columns → correct error
   - Question with no chips and `free_text_allowed = NO` → error
   - Duplicate chip slug within question → error
   - UTF-8 BOM stripped
   - CRLF line endings accepted
   - Empty file (headers only) → error "no question rows"
   - `question_position` 1-indexed → converted to 0-indexed in output

**Checkpoint**: `pnpm --filter @legal-chatbot/api exec vitest run src/lib/branch-csv.test.ts` all pass.

---

### Phase 1 — API Routes

**Goal**: Two new Next.js route handlers.

3. Create `packages/api/src/app/api/dashboard/branches/[caseType]/[subType]/template/route.ts`:
   - `GET` handler: authenticates session, calls `generateTemplateCsv(caseType, subType)`, returns response with `Content-Type: text/csv` and `Content-Disposition: attachment; filename="branch-template-[caseType]-[subType].csv"`.

4. Create `packages/api/src/app/api/dashboard/branches/[caseType]/[subType]/import/route.ts`:
   - `POST` handler: authenticates session, reads `multipart/form-data` for the `file` field, checks file size (reject > 500 KB with 413), checks file extension/content-type (reject non-CSV with 400), calls `parseAndValidateCsv`, returns either `{ ok: true, questions }` (200) or `{ ok: false, errors }` (422).

5. Add integration tests for both routes in `packages/api/src/app/api/dashboard/branches/handler.test.ts` (or new sibling files):
   - Template: returns CSV with correct headers and filename.
   - Import happy path: valid CSV → 200 with questions.
   - Import format error: wrong extension → 400.
   - Import validation error: bad row → 422 with errors.
   - Import size error: oversized file → 413.

**Checkpoint**: `pnpm --filter @legal-chatbot/api exec vitest run` all pass.

---

### Phase 2 — Dashboard UI (`branch-editor.tsx`)

**Goal**: Import and template buttons wired to the new APIs; inline preview/error state.

6. In `packages/api/src/app/dashboard/sop/branch-editor.tsx`:
   - Add `importState: 'idle' | 'uploading' | 'error' | 'preview'` to component state.
   - Add `importErrors: CsvError[]` and `importedQuestions: BranchQuestion[] | null` to state.
   - Add **"Download CSV Template"** button: `<a href="/api/dashboard/branches/[caseType]/[subType]/template" download>` — no JS needed, plain anchor download.
   - Add **"Import from CSV"** button: opens `<input type="file" accept=".csv" />` via a ref click. On file selection, `POST` to the import route with `FormData`, update `importState`.
   - Render **error table** when `importState === 'error'`: columns Row, Column, Issue; one row per error.
   - Render **preview table** when `importState === 'preview'`: list of questions with their chips and weights; "Save as Draft" and "Cancel" buttons.
   - "Save as Draft": calls the existing `handleSave` with `importedQuestions` replacing `questions` in the PUT body. Thresholds and overrides are read from current component state (already loaded from the existing branch version, or defaults if none).
   - "Cancel": resets `importState` to `'idle'` and clears `importedQuestions`.
   - Navigation-away warning: if `importState === 'preview'` and user clicks away, show `confirm()` dialog.

**Checkpoint**: Dashboard renders import/template buttons; valid CSV upload shows preview; save creates new draft version visible in branch history.

## Notes

- The template download is a plain `<a href="..." download>` — no JavaScript, no fetch. The browser handles the download natively. This is the simplest possible implementation.
- The `branch-csv.ts` module is intentionally isolated from the handler module so it can be unit-tested without any HTTP or DB scaffolding.
- The `preface` field (optional lead-in text per question) is not in the CSV template. It remains editable only via the manual editor. This is a known limitation documented in the spec's Out of Scope section.
- Classification thresholds are inherited from the current branch version state already loaded in `BranchEditor` at import time — no extra DB round-trip needed.
