# Data Model: Deployment & Release

**Date**: 2026-05-23
**Plan**: [plan.md](./plan.md)
**Spec**: [spec.md](./spec.md)

Deployment & Release introduces NO new persistent application
entities. Its "data model" consists of release artifacts,
operational records (release notes / changelog), and
release-gate state (eval pass/fail records).

## Release Artifacts

| Artifact | Producer | Distribution | Versioning |
|---|---|---|---|
| **API + Dashboard Netlify site** | `packages/api` build → Next.js | Netlify (production URL) | Continuous deploy from `main` |
| **Widget + Demo Netlify site** | `packages/widget` build → Vite static | Netlify (production URL) | Continuous deploy from `main` |
| **Crawler npm package** | `packages/crawler` build | npm registry (`legal-chatbot-crawl` or `@legal-chatbot/crawl`) | Changesets-managed semver |
| **Widget npm package** | `packages/widget` build | npm registry (`@legal-chatbot/widget`) | Changesets-managed semver |
| **Production Neon database** | `packages/api/drizzle/` migrations | Neon (managed) | Append-only migrations via drizzle-kit |
| **Conversation-quality eval results** | `evals/run-evals.ts` execution | `evals/runs/<date>.md` (committed) | Per-release-cycle |
| **Release notes / CHANGELOG** | Changesets `pnpm changeset publish` | `packages/widget/CHANGELOG.md`, `packages/crawler/CHANGELOG.md` | Per-version |

## Configuration Files (added by this feature)

### `.github/workflows/ci.yml` (R1)

GitHub Actions workflow. Triggered by `pull_request` and
`push` to `main`. Stages per §9.10.

### `.github/workflows/release.yml` (R8)

GitHub Actions workflow. Triggered by Changeset release PRs
merging to `main`. Calls `pnpm changeset publish`.

### `.changeset/config.json` (R4)

Changesets configuration. Lists ignored internal packages.

### `packages/widget/.size-limit.json` (R3)

Bundle-size budget configuration. Two budgets matching
Constitution Architectural Limits.

### `packages/api/tests/e2e/playwright.config.ts` (R2)

Playwright config. Base URL, browser, timeout, trace settings.

### `evals/scenarios/*.yml` (R5)

Conversation-quality scenarios. One YAML per test case.

### Changelog Records

`packages/widget/CHANGELOG.md` and

## Validation Rules

| Boundary | Validator | On failure |
|---|---|---|
| CI workflow YAML | GitHub Actions parser | workflow rejected |
| `.changeset/config.json` | Changesets parser | publish step fails |
| `.size-limit.json` budgets | size-limit parser | non-zero exit |
| Playwright `playwright.config.ts` | Playwright TS-config loader | test run fails |
| Eval scenarios YAML | hand-rolled YAML parser + Zod schema | scenario skipped with warning |
| Production migration | Drizzle migration tooling | aborts before any partial write |

## State Transitions

### Release Pipeline

```text
[code on main]
    │
    ├── PR opened ──▶ ci.yml runs ──▶ stages 1-5 + size-limit + invariants
    │                       │
    │                       ├── pass ──▶ ready to merge
    │                       └── fail ──▶ blocked by branch protection
    │
    ├── PR merged to main ──▶ ci.yml runs ──▶ stages 1-6 (incl. E2E)
    │                              │
    │                              └── pass ──▶ Netlify rebuilds; deploys
    │
    └── Changeset version PR ──▶ release.yml runs ──▶ pnpm changeset publish
                                       │
                                       ├── npm packages published
                                       ├── git tags created
                                       └── CHANGELOG.md updated
```

### Eval Pipeline (manual)

```text
[release engineer triggers eval]
    │
    └── pnpm eval ──▶ run-evals.ts iterates scenarios
                          │
                          ├── per-scenario pass/fail
                          └── aggregate pass rate ≥ 90%? ──▶ commit run record
                                                              │
                                                              ├── ≥ 90% ──▶ PROCEED
                                                              └── < 90% ──▶ BLOCK release
```

## Schema Migration Strategy

Production database migration is **manual** per R10:

1. Engineer ensures all migrations in
   `packages/api/drizzle/` are committed.
2. Engineer runs `DATABASE_URL=<prod> pnpm db:migrate` from a
   trusted machine.
3. Drizzle's migration tooling handles idempotency.
4. The seed script (R6 guard) blocks accidental seed.

Future post-MVP: a GitHub Actions workflow gated on a special
`production-migrate` label could automate step 2.

## Release Cadence

- **Code changes**: any merge to `main` triggers Netlify
  rebuild → continuous production deploy.
- **NPM packages**: only Changeset-driven version PRs trigger
  npm publish — engineers explicitly decide when to bump.
- **Database migrations**: manual per R10 — never automatic.
