# Contract: System Prompt Extension

**Owner**: SOP Workflow (`010-sop-workflow`)
**Extends**: `004-chat-api-agent` `system-prompt-contract.md` Block 4 (Intake state).
**Source of Truth**: spec.md FR-055, FR-024, FR-029-FR-032, R5 off-SOP detour.

## Block 4 Replacement (Intake State → SOP State)

The §7.8 four-block system prompt structure remains intact. Block 4 (formerly "Intake state — questions asked/remaining") is REPLACED with **SOP State**, generated by `lib/sop/system-prompt-extension.ts`.

The composer is invoked with the current `SOPState` and produces a Markdown block injected at Block 4's position in the system prompt.

## Block Layout

```
## SOP State

You are following a Standard Operating Procedure (SOP) to capture lead-qualification information. Track which steps have been answered and direct the conversation toward the next pending step.

### Steps (in order)

1. [✓] case_type — "DUI" (captured)
2. [✓] sub_type — "first_offense" (captured via chip)
3. [ ] where — PENDING (next to ask)
4. [ ] what — pending
5. [ ] when — pending

### Current pending step

Ask the visitor: "Where did this happen?"
This step accepts free-text answers; no chips.

### Skip detection

If the visitor's next message answers MULTIPLE pending steps in one response, mark all answered steps as captured and ask only the EARLIEST pending unanswered step next.

### Off-SOP detour rule

If the visitor's next message is unrelated to the current pending step (e.g., asks about office hours), answer their question first within your guardrail boundaries, THEN end your response by asking the current pending step's question.

### Completion behavior

After all 5 steps are complete you will be instructed (via a tool result) to either generate 2-5 follow-up questions or finalize the lead.

### Goodbye behavior

You MUST NOT bid goodbye unless the visitor has explicitly said one of: "bye", "goodbye", "thanks", "thank you", "good night", "see you", "that's all". Otherwise every response ends with the next pending SOP step OR (when SOP is finalized) an open re-prompt: "Is there anything else I can help you with?".
```

## Variations by State

| State | Block content |
|---|---|
| All steps `pending` | Lists steps; current pending is step #1; standard skip + off-SOP + goodbye rules. |
| Some steps `complete` | Marks captured steps with [✓] and shows captured value (truncated 30 chars, PII-redacted). Current pending is the earliest `pending` step. |
| All steps `complete` AND `is_finalized=false` | Block instructs the agent to call the `analyzeAndFollowUp` tool. Goodbye rule still applies. |
| `is_finalized=true` (Step 6 finalize OR out-of-scope termination) | Block omits step list. Block instructs: "SOP complete. Continue answering visitor questions within guardrails. End every response with an open re-prompt unless the visitor says goodbye." |
| `out_of_scope_termination=true` | Block instructs agent to use the configured out-of-scope deflection AND continue answering further questions about other matters. |

## Token Budget

The block MUST stay within the §7.7 ~1000-token guardrails-block budget plus a ~500-token SOP appendix. Specific size by SOP length:

- Default 5-step SOP: ~350 tokens.
- 10-step SOP: ~600 tokens.
- 20-step SOP: ~1100 tokens (approaching the cap).

Implementation: the composer truncates captured-value summaries to 30 chars to keep the block bounded.

## Integration with Existing Composer

`packages/api/src/lib/system-prompt.ts` is extended:

```ts
// Existing function signature unchanged from Phase 3
export function composeSystemPrompt(
  config: Configuration,
  guardrailsMarkdown?: string,
  sopState?: SOPState,                         // NEW optional param
  sopConfig?: SOPConfiguration,                 // NEW optional param
  goodbyePhrases?: string[],                    // NEW optional param
): string {
  // ... existing Block 0, 1, 2 composition unchanged ...

  // NEW Block 4: SOP State (replaces legacy intake state block)
  if (sopState && sopConfig) {
    parts.push(composeSopBlock(sopState, sopConfig, goodbyePhrases ?? DEFAULT_GOODBYE_PHRASES));
  } else {
    // Fallback to legacy §7.5 intake-question flow if no SOP exists for the account
    parts.push(composeLegacyIntakeBlock(config));
  }

  return parts.join('\n');
}
```

The existing legacy `composeLegacyIntakeBlock` is preserved for accounts that haven't migrated yet (per R11 lazy migration).

## Determinism

Given identical SOP state + SOP configuration + goodbye phrases, the composer produces byte-identical output. This is a unit-testable property and required for `--deterministic` E2E test runs.

## Tests

`packages/api/src/lib/sop/system-prompt-extension.test.ts` MUST cover:

- All-pending state → block lists all steps with [ ] and current pending is step 1.
- Mid-flow state → block shows [✓] for completed steps with captured values.
- All-complete state → block instructs `analyzeAndFollowUp` tool invocation.
- Finalized state → block has no step list; only post-finalization rules.
- Out-of-scope state → block instructs deflection + open re-prompt.
- Captured-value PII redaction (email, phone, name patterns stripped from displayed captured values).
- Token-budget regression test: 20-step SOP block ≤ 1100 tokens.
